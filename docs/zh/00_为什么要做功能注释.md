# 为什么要做功能注释？

> 本课只讲 **WHY**。怎么跑 → [03](03_怎么开始跑.md)；门禁 → [10](10_验收_FL0_FL1.md)；英文 [`../EVALUATION.md`](../EVALUATION.md) / [`../ROADMAP.md`](../ROADMAP.md)。

## 功能是第二层，不是结构的「彩蛋」

结构注释交出 **GFF + proteins** 之后，读者仍会问：

- 这条蛋白**像**已知的什么？  
- 有没有可转移的 GO / 通路提示？  
- 有哪些**结构域**支撑机制假设？

功能注释回答的是「像什么 / 带什么标签」，产物是以基因为行的 **`functional_master.tsv`**（再打 release），不是再画一遍外显子。

Ji *NRG* 2026：功能是结构之上的第二层（同源命名、结构域、通路等）。两仓分工与此一致。

## 为什么需要单独一层（而不是「BLAST 一下写进 GFF」）？

| 理由 | 说明 |
|------|------|
| **可对账** | 总表一行一基因；与 `PROTEINS_FA` 来源 TAG 绑定 |
| **多证据正交** | 名字线索 ≠ 直系同源转移 ≠ 结构域（见 [13](13_为什么F1是三件套.md)） |
| **可复现** | DB/软件版本钉死；避免「某次网页 BLAST」不可引用 |
| **等级诚实** | F-L0 / F-L1；快框与论文骨架分开 |

**反例：** 把一次 `blastp` top hit 的标题粘进 GFF 第 9 列，声称「完成功能注释」— 无版本、无合并、无门禁。

## 功能注释修不了什么（必须诚实）

FA **不能**修复：

- 错误外显子 / 碎裂 / 邻位融合  
- TE 假基因、串联家族塌缩  
- 结构仍是 L0 时的「看起来很完整」幻觉  

F0 蛋白 BUSCO 灾难 → **停 FA，回结构**（见 [14](14_为什么先结构后功能.md)）。

**反例：** 给明显的 TE ORF 贴满 GO 与结构域 — 表越漂亮，误导越大。

## 和 EVALUATION / ROADMAP 的挂钩

- 默认脊柱：`F0 → F1 → merge → release`  
- 替代框（F2/F3/F5）与加件（F4/F6/…）不得冒充更高真理  
- 版本与谱系必须写清 → [15](15_为什么版本和谱系必须写清.md)
