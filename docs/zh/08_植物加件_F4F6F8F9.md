# 植物加件：F4 / F6 / F8 / F9（+ F7 简述）

**全部挂在 F1（或替代框）之后**，不能单独冒充「更高真理」。  
英文：[`../FUNCTIONAL_GUIDE.md`](../FUNCTIONAL_GUIDE.md) · [`../ROADMAP.md`](../ROADMAP.md)

## 为什么

1. 植物论文常要**可读名 / MapMan / NLR / TF** — 但它们挂在主干之后。  
2. 加件不创造更高验收档；F-L1 看门禁。  
3. 没跑就写 unused，避免暗示。  
4. F7 OrthoFinder 是多基因组策略，单基因组默认不必先跑。  
5. NLR 候选仍可能要回结构窗核查坐标。

**反例：** METHODS 写「完成 MapMan」，`mercator/` 目录为空。
## F4 — AHRD 可读基因名

把 DIAMOND（± InterPro）证据喂给 AHRD，产出 human-readable description，再 `F4_join_ahrd.py` 拼进 master。  
教学点：名字是**选出来的描述**，不是数据库权威 ID；可与 PANNZER（F4b）对照，勿幻觉基因符号。

## F6 — Mercator4 / MapMan BIN

植物通路语言。Mercator4 **无公开 CLI** → 网页上传蛋白 → 下载结果 → `F6_ingest_mercator.py`。  
大文件需分块上传。没跑就别在 METHODS 暗示「做了 MapMan」。

## F8 — NLR candidates / screen（候选筛，不是全库 census）

InterPro 域过滤 ± HRP。产出候选表（如 `nlr_candidates.tsv`）。结构不确定时回 GSAman 看坐标；功能行可保留即使表达低。

## F9 — iTAK（TF / 激酶）

植物转录因子与蛋白激酶分类。论文要画 TF 家族图时再上；动物/真菌项目通常无关。

## F7 — OrthoFinder（简述）

多基因组时先建正交群，对**代表序列**跑 F1，再按 METHODS 声明的多数规则回填。  
顺序：`F7 → F1 on reps → merge`。单基因组默认**不必**先 OrthoFinder。

## 典型植物论文组合

```text
F0 → F1 → merge → (F4 AHRD join) → (F6 Mercator ingest) → (F8/F9) → release
最小真核：F0 → F1 → merge → release
```
网页 Mercator 可与 F1 **并行**提交；**ingest 必须在 merge 之后**（需要 `functional_master.tsv`）。

加件**不**单独抬高验收等级；F-L1 看的是主干门禁（见 [10](10_验收_FL0_FL1.md)）。
