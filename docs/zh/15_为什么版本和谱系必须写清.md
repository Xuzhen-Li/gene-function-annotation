# 为什么版本和谱系必须写清？

> WHY 深课。安装配对见 [`../INSTALL_FUNCTIONAL.md`](../INSTALL_FUNCTIONAL.md)；翻车 [12](12_常见翻车.md)；英文 [`../EVALUATION.md`](../EVALUATION.md) 门 F2/F4。

## 1. eggNOG：mapper 与 DB 必须配对

eggNOG-mapper **主版本**与 eggNOG **数据库主版本**是契约关系。  
典型红线：`emapper v3` 配 `eggNOG v5`（或未声明的错配）→ 空表、列错义、不可比。

本仓教学默认：**emapper v3 ↔ eggNOG v7**（以 INSTALL / 上游文档为准；METHODS **两侧都写**）。

**反例：** 只写「eggNOG-mapper」不写 DB 版本 — 他人无法复现，门 F4 失败。

## 2. InterPro：扫描器版本 + 成员库日期

InterProScan 输出依赖：

- 软件主/次版本；  
- 背后 InterPro / 成员库（Pfam、SMART…）的 **数据发布**。

只写「跑了 IPS」无法解释域集合差异；论文应同时钉死版本（并宜引用 InterPro *NAR* 数据库文，见 [`../REVIEWS.md`](../REVIEWS.md) / RECENT_HIGH_QUALITY）。

**反例：** 两年前 IPS 与今年 IPS 比「谁域更多」却不报库日期。

## 3. BUSCO 谱系（F0 / 结构 G6）

功能仓 F0 与结构仓 G6 都要求：**Completeness 数字 + 谱系全名**。  
谱系决定直系同源集合；植物/动物/真菌混用默认库 → 百分比无意义。

**反例：** FA METHODS 写「protein BUSCO 96%」不写 `viridiplantae_odb12` — 门 F2 意图失败。

## 4. Swiss-Prot / DIAMOND 也要钉

Swiss-Prot **release 日期或版本**、DIAMOND 软件版本 → 影响 hit 标题与可重复性。  
「用了 UniProt」太粗。

## 5. 为什么这是门禁不是洁癖？

| 不写清 | 后果 |
|--------|------|
| Mapper/DB 错配 | 科学上错或空；自动不合格条款 |
| 无谱系 | 跨项目横比谎言 |
| 无结构 TAG | 功能与模型脱节 |
| 暗示未跑的加件 | 审稿对照目录即穿帮 |

诚实写法：用了写版本；没用写 **unused**；waiver 写框名。
