# 为什么 F1 是「三件套」？

> WHY 深课。逐步操作见 [06](06_F1精讲_DIAMOND_eggNOG_IPS.md)；英文 [`../FUNCTIONAL_GUIDE.md`](../FUNCTIONAL_GUIDE.md) · [`../REVIEWS.md`](../REVIEWS.md)。

## 三根柱子各补一块盲区

| 柱 | 工具 | 回答的问题 | 盲区（若单独用） |
|----|------|------------|------------------|
| F1a | **DIAMOND × Swiss-Prot** | 最像哪条**高质量**蛋白？ | 最佳命中 ≠ 直系同源；易「乱贴名字/GO」 |
| F1b | **eggNOG-mapper** | 偏**直系同源**的功能转移 | 无域级机制证据；DB/mapper 错配会空表 |
| F1c | **InterProScan** | 有哪些**结构域 / 签名**？ | 有域可以仍无可读名；不算正式基因符号 |

合并成 master：**线索 + 转移 + 机制**同表可对读。

## 为什么不是「只跑 BLAST」？

经典翻车：`blastp` 最佳命中 → 直接把对方 GO/名字抄过来。

问题：

1. **同源 (homology) ≠ 直系同源 (orthology)** — 旁系/远同源也会高分；  
2. Swiss-Prot 标题是**描述字符串**，不是你的基因正式名；  
3. 无结构域交叉验证时，假阳性命名很难自检；  
4. 不可复现的「某次网页 BLAST」进不了严肃 METHODS。

DIAMOND×Swiss-Prot 保留「高质量同源线索」，但必须与 eggNOG / IPS **同表**，并在 METHODS 写「transferred from…」。

**反例：** 仅 BLAST 命中率 80% 就宣称「CAFA 级 GO 精度」— 自动不合格叙事。

## 直系同源 vs 同源（教学一句）

- **同源：** 序列有共同祖先痕迹（DIAMOND 擅长找）。  
- **直系同源（工作定义）：** 物种分化后对应的那份 — eggNOG 等图谱用这个假设做**更谨慎的功能转移**。  
仍不是湿实验验证；CAFA 电子预测亦有上限（见仓库 haul / RELATED_SOFTWARE 备注）。

## 结构域 vs 名字

| | 结构域（IPS） | 名字 / GO（emapper、AHRD…） |
|--|--------------|------------------------------|
| 性质 | 序列上的机制零件 | 可读标签 / 本体词 |
| 可空 | 有域无 GO 常见 | 有 GO 无域也常见 |
| 误用 | 把域当基因符号 | 把 hit 标题当官方 ID |

**反例：** InterPro 检出 NB-ARC 就写基因名 `NLR1` 而不做 F8/结构窗核查。

## 为什么默认要三件都进 merge？

F-L1 的 **Gate-F3**：默认 **F1 三件套**，或书面 waiver 点名替代框。  
缺 IPS 的快框（F2）通常停在 **F-L0**，直到补进 merge。

**反例：** 只交 `diamond/swissprot.tsv` 文件夹当放行 — 无 master、无版本钉死、无门禁。
