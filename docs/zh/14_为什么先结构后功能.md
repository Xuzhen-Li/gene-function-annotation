# 为什么先结构后功能？

> WHY 深课。关系课 [02](02_和结构注释的关系.md)；F0 [05](05_F0蛋白BUSCO.md)；结构仓 [`docs/zh`](https://github.com/Xuzhen-Li/gene-structure-annotation/tree/main/docs/zh)。

## 1. Provenance：功能表必须能对上基因模型

`PROTEINS_FA` 必须带来源：结构 `RELEASE_TAG` 或内容哈希（**Gate-F1**）。  
没有 provenance：

- 结构改了两轮，功能表还在评旧肽段；  
- 审稿人无法复现「哪个 GFF 生出这些标签」；  
- 跨层对账失败。

**反例：** 匿名 `proteins.faa` 丢进 FA，METHODS 只写「from our annotation」— F1 不合格。

## 2. 灾难性 F0：为什么是急刹车？

InterProScan 等步骤 **CPU/墙时很贵**。  
若蛋白集已灾难性 Missing/Fragmented，先烧 FA 只会生产**大规模错误标签**。

F0 = 功能侧花费闸 + 跨层警告：崩了 → **停 FA，回结构 EVALUATION**，不是「先注释着」。

**反例：** F0 显示 M 极高仍开满 IPS，一周后发现 GFF 抽蛋白路径错了。

## 3. 装饰坏模型更糟，不是「至少有张表」

错误坐标、TE ORF、塌缩串联上的漂亮 GO：

- 误导比较基因组与通路富集；  
- 让人以为结构「已经够好」；  
- 违反两层诚实叙事（结构 L0 → FA 只能 provisional）。

功能仓**不策展外显子**；错位点回结构 GSAman。

**反例：** 「功能注释很全，所以结构应该没问题」— 逻辑反了。

## 4. 等级传递

```text
结构 L1 / L2  →  才适合冲 FA F-L1
结构 L0       →  FA 最多 F-L0 / provisional
F0 灾难       →  停 FA
```
